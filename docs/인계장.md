## 2026-11-21 — [유지보수 · 사용자 요청] 터치 도움 (살짝 빗나가거나 미끄러져도 인정)

**사용자 질문:** "터치 감도 조정이나 살짝 주변을 눌러도 허용되게 할 수 있나?" → 가능하다고 답하고, 사용자가 **부모 설정으로**(끔/보통/넉넉하게, 기본 보통)를 골랐다.

**원인 분석:** 모든 탭을 브라우저 기본 `click`으로 받고 있었다. 기본 클릭은 누른 채 손가락이 약 10px만 움직여도 취소되고, 대상 사이 빈틈(최소 24px)은 무시된다. 화면 자체의 터치 감도는 앱이 못 바꾼다(갤럭시탭 설정 → 디스플레이 → 터치 민감도 안내).

**설계서 먼저:** §1 "터치 도움" 규칙, §9 설정 표 "터치 도움" 행.

**구현 (`js/touch.js` 신규)**
- pointerdown(캡처): 아이 화면(메인·게임·포도판·쉬는 시간)에서 댄 곳이 버튼이면 그 버튼, 아니면 반경(보통 24 / 넉넉하게 48px) 안 가장 가까운 "눌릴 수 있는" 버튼. 눌릴 수 있음 = 비활성 아님 + 버튼 한가운데의 `elementFromPoint`가 그 버튼(가려짐·숨김·pointer-events:none 제외). 가장 가까운 둘의 거리 차가 2px 미만이면 무시.
- pointerup: 2초 안이고, 뗀 곳이 그 버튼에서 max(반경, 24px) 안이면 `button.click()`. 손가락(pointerId)마다 따로.
- 브라우저의 원래 클릭(isTrusted)은 아이 화면에서 막는다(두 번 눌림 방지). 시작 ▶(소리 활성화는 원래 탭 필요)과 부모 진입(3초 누르기)은 제외.
- 켜져 있으면 아이 화면에 `touch-action: none`(움직일 때 브라우저가 터치를 가져가 pointercancel 내지 않게).
- `settings.js` `touchHelp`(기본 normal), `main.js`(initTouch·적용), `parent.js` 화면 탭 "터치 도움" 칩, `sw.js`에 touch.js 추가·CACHE_VERSION 31 → 32.

**검사 (`dev/tests/touch.mjs` 신규, CDP 실제 터치 입력) 15/15**
- 정확히 누름 1번만 셈, 빈틈 10px → 가까운 물체, 두 물체 정확히 가운데 → 무시, 60px 밖 → 무시, 누른 채 15px 밖으로 미끄러짐 → 인정, 2.3초 누름 → 무시, 한 손가락을 빈 곳에 올린 채 다른 손가락 → 인정, 넉넉하게 40px → 인정, 끔 → 빈틈 무시·정확히는 1번·touch-action 기본, 시작 ▶ 터치 → 메인, 부모 3초 누르기 그대로.
- 처음 실패 4건은 검사 실수(물체가 2줄일 때 "60px 아래"가 둘째 줄 물체를 정확히 누름 → 연쇄). 빈 곳을 첫 물체 왼쪽 60px로 바꿈.

**검사 도구 흔들림 수정:** 전체 실행 중 buddy가 가끔(1/6 정도) "처음 메인 캐릭터"에서 실패. 측정해 보니 앱 준비(게임 버튼이 그려지는 시각)가 0.65~1.2초 이상 들쭉날쭉한데 검사는 고정 1.5초 뒤에 눌러, 바쁠 때 준비 전에 눌렀다. `lib/cdp.mjs`에 `openApp`/`reloadApp`/`appReady`(게임 버튼이 생길 때까지 기다림)를 넣고 모든 검사에 적용. 앱 문제 아님(실기기는 캐시라 빠르고, 준비 전 탭은 다시 누르면 된다).

**결과:** 전체 84/84 통과를 두 번 연속(10개 검사, 약 210초).

## 2026-11-21 — [7단계 · 사용자 요청] 부모 설정에서 효과음 소리 고르기

**사용자 요청:** "그냥 효과음도 종류별로 설정에서 정할 수 있게 해 줘."
- 해석: 비교 화면의 소리 종류(글로켄·피아노·부드러운 피아노·오르골) 중 하나를 부모 설정에서 고르면 효과음 4종에 모두 적용. 소리별(톡·띵동 따로) 지정은 하지 않았다(필요하면 추가 가능하다고 안내). v29의 "배음+유지" 소리는 사용자가 싫다고 해서 뺐다.

**설계서 먼저:** §7 효과음 소리(4종 부분음 표·boost), §9 설정 표 "효과음 소리" 행.

**수정**
- `js/audio.js`: `SFX_STYLES`(소리별 부분음·감쇠·attack·boost) export, `config.sfxStyle`, `configure({ sfxStyle })`, `bell()`이 지금 소리를 읽음, 효과음 게인 = 음량 × 소리별 boost.
- 크기 맞추기(실제 audio.js 렌더링 측정): 피아노가 약 2dB 작아 boost 2.6 → 3.1, 부드러운 피아노는 음량 100% 짜잔이 1.03이라 3.0 → 2.7. 그래도 피아노 계열 짜잔이 1.00~1.01이라 `SFX_TRIM` 0.8 → 0.76.
  - 결과: 네 소리 모두 최대 0.96 이하, 음량 60% 띵동 −9.4(오르골)~−11.4dB(피아노).
- `js/settings.js`: `sfxStyle` 기본 'glocken', 선택지 밖 값은 기본값. `js/main.js`: audio에 전달.
- `js/parent.js`: 소리 탭 "효과음 소리" — 🔔 글로켄 / 🎹 피아노 / 🎹 부드러운 피아노 / 🎶 오르골 칩(고르면 띵동 미리 듣기) + 🔈 톡·띵동·쏙·짜잔 듣기 버튼.

**검증 (헤드리스 Edge):** 기본 glocken, 칩 8개 표시, "부드러운 피아노" 누르면 설정·audio 모두 softPiano, 듣기 버튼 4개 동작, 새로고침 후 유지, 잘못된 값('trumpet')은 sanitize → glocken·setSetting 거부. 오류 0.

## 2026-11-21 — [7단계 · 사용자 피드백] 효과음 소리를 글로켄(벨)으로

**사용자 의견:** "효과음은 커졌는데 소리 스타일이 좋지 못하다. 부드러운 피아노나 벨 소리로."(v29의 배음 섞은 파형 + 최고 크기 유지가 웅웅거리는 오르간처럼 들린 것으로 보인다)

**고르는 방법:** `dev/sfx.html`(신규, 개발용, 배포 안 함)에 5줄(지금 v29 / 피아노 / 부드러운 피아노 / 벨(글로켄) / 부드러운 벨(오르골)) × 4칸(톡·띵동·쏙·짜잔)을 만들어 PC에서 들어 보게 했다. 크기는 모두 v29 수준 이상으로 맞췄다(측정). 사용자가 **글로켄**을 골랐다.

**수정 (`js/audio.js`, 설계서 §7 먼저)**
- `tone()` → `bell()`: 사인파 부분음 4개(1 : 2.76 : 5.4 : 8.93, 세기 1 : 0.35 : 0.12 : 0.05), 2ms 올라감 → `setTargetAtTime` 지수 감쇠, 높은 부분음일수록 빨리 사라짐. `PeriodicWave` 파형은 지웠다.
- 효과음 4종 음 높이는 그대로, 길이는 벨에 맞춰 0.35~1.1초. 톡은 자주 나서 세기 0.55.
- `SFX_BOOST` 1.8 → 2.4, 리미터 뒤 `SFX_TRIM` 0.8 추가. 처음엔 벨의 빠른 시작이 리미터를 지나 최대 1.20(음량 100% 짜잔)까지 튀었다.

**검증 (실제 audio.js, OfflineAudioContext 2초 렌더링)**

- 음량 100%: 최대 0.65~0.96(1 미만). 오류 0.
- `sw.js` CACHE_VERSION 29 → 30.

## 2026-11-21 — [7단계 · 실기기] 효과음 2차 키움 (배음 + 유지 + 리미터)

**사용자 의견(업데이트된 탭):** "효과음은 아직도 좀 작다, 더 키워 달라."

**원인:** 1차(v26)는 최대값만 키웠는데, 소리가 나자마자 빠르게 줄어드는 모양(지수 감쇠)이라 평균 크기가 낮았다. 순수 사인파라 작은 스피커에서 덜 또렷했다.

**후보 측정 (헤드리스 Edge `OfflineAudioContext`, 음량 60%, "띵동" 소리 에너지)**
| 안 | 에너지 | 최대 |
|---|---|---|
| 처음(v25) 사인 0.22 | −35.7dB | 0.13 |
| 1차(v26) 0.65 + 압축기 | −23.1dB | 0.63 |
| A 배음 + 리미터 | −20.8dB | 0.90 |
| **C 배음(1:0.5:0.25) + 절반 유지 + 1.3배 길이 + ×1.8 + 리미터** | **−10.7dB** | 0.95 |
| D C보다 강하게 | −9.8dB | 1.06(넘침) |
→ C 채택. 1차보다 약 12dB(체감 약 2배 이상).

**수정 (`js/audio.js`, 설계서 §7 먼저):** `PeriodicWave` 파형, 엔벨로프 0.015초 올라가 길이 절반까지 0.95 유지 후 감쇠, 효과음 4종 길이 1.3배, `SFX_BOOST = 1.8`, 압축기 → 리미터(threshold −3dB, knee 0, ratio 20, attack 1ms). 처음 −2dB에서는 음량 100%일 때 최대 1.01이 나와 −3dB로 낮췄다.

**검증 (실제 audio.js, AudioContext를 OfflineAudioContext로 바꿔 끼워 렌더링):** 음량 60% — 톡 −19.9 · 띵동 −11.1 · 쏙 −16.3 · 짜잔 −8.7dB, 최대 0.90~0.92. 음량 100% — 최대 0.96~0.97(1 미만). 오류 0. `sw.js` CACHE_VERSION 28 → 29.

**참고:** 리미터 때문에 음량 60%와 100%의 차이가 작다(약 0.5dB). 더 작게 하고 싶으면 60% 아래로 내리면 줄어든다.
