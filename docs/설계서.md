## 1. 화면 색상·시각 자극 (유아 시력 보호)
- 모든 색상은 css/style.css 최상단 `:root` CSS 변수로만 정의하고, 다른 곳에 색상값을 직접 쓰지 않는다.
- 순백색(#FFFFFF)·순검정(#000000) 사용 금지. 원색·형광색·고채도 빨강 금지.
- 기본 팔레트 (따뜻하고 채도 낮은 파스텔):
  - 배경 `--bg: #FAF6EE` (크림)
  - 카드·패널 `--surface: #FFFDF8`
  - 숫자·주요 형태 `--ink: #4A4038` (진한 웜그레이, 배경 대비 약 9:1로 또렷함 유지)
  - 보조 선·비활성 `--muted: #B8AFA4`
  - 포인트 5색(게임별 구분용): 세이지 `#A8C3A0`, 하늘 `#A7C7DC`, 살구 `#F2C6A0`, 버터 `#F3DE9A`, 라벤더 `#C9BEDF`
  - 정답 반응 `--success: #E9C46A` (은은한 금빛 글로우)
  - 힌트 강조 `--hint: #8FB8A8`
- 한 화면에 쓰는 포인트 색은 최대 3가지. 배경 무늬·그라데이션 남용 금지.
- 색만으로 정보 전달 금지(색각 이상 대비): 정답·선택 상태는 크기·테두리·움직임을 함께 사용.
- 대상 강조는 깜빡임 대신 "크기 변화"와 "흔들림"으로 한다 (시각 보호):
  - 주목·힌트: 대상이 1.0 → 1.15배로 천천히 커졌다 돌아오기(1회 0.8초, 최대 3회).
  - 정답 위치 알려 주기: 좌우로 살짝 흔들기(±6도, 0.5초, 최대 2회).
  - 선택됨·센 물체: 1.1배 커진 상태 유지 + 테두리 두껍게(--ink 4px).
  - 자체 테두리 색을 선언한 대상(숫자 카드·접시·돌 등)은 그 선언이 `.is-marked`보다 뒤에 있으면 진한 테두리가 덮어써진다. 그런 대상은 `.대상.is-marked { border-color: var(--ink) }`를 따로 둔다. 새 대상을 추가할 때 mark 상태의 테두리 색을 실제로 확인한다.
  - 도형·숫자 카드·물체 모두 같은 방식 적용. 공통 함수로 js/effects.js에 `pulse(el)`, `wobble(el)`, `mark(el)`를 만들어 재사용한다.
  - 무응답 힌트도 끝없이 반복하지 않는다. 누르지 않고 연달아 내는 힌트는 **최대 3번**이고, 그 뒤로는 조용히 기다린다. 아이가 한 번이라도 누르면 다시 0부터 센다(`common.js`의 `MAX_IDLE_HINTS`).
- 깜빡임(점멸·밝기 반복)은 원칙적으로 사용하지 않는다. 크기·흔들림으로 대체할 수 없어 꼭 필요한 경우에만, 작은 영역에서 1초 이상 천천히 1~2회로 제한하고 코드 주석에 사유를 적는다. 초당 3회 이상 점멸은 어떤 경우에도 금지(광과민성 발작 예방).
- 애니메이션: 0.3~0.6초 ease-in-out, 화면 전체가 흔들리거나 번쩍이는 효과 금지. 화면 전환은 부드러운 페이드.
- **지원 화면 크기(가로, CSS px):** 기준 1280×800. 최소 962×601(갤럭시탭 A 8.0급)부터 1440×900까지, 그리고 앱 설치 없이 브라우저 주소창이 있는 1280×744에서 모든 아이 화면이 잘리지 않고 120px·24px 규칙을 지켜야 한다. 확인은 이 크기들로 가장 많은 물체가 나오는 문제를 그려서 한다.
  - 게임 화면 위쪽 여백은 156px(🏠 아래 끝 136px + 여유), 메인 화면 위쪽 여백은 124px(⚙️ 아래 끝 100px + 24px)다. 낮은 화면에서 내용이 위로 밀려도 고정 버튼과 겹치지 않게 하기 위해서다.
  - 낮은 화면에서는 장식(결과 숫자 카드·콩콩이 등)을 `vh`로 줄이고, 아이가 누르는 대상의 120px 최소는 줄이지 않는다.
  - 한 줄 5개 배치는 그 칸이 줄어들지 않게(`flex-shrink: 0`) 하고 옆 요소가 폭을 양보한다.
- 화면 전환 중 사라지는 화면은 즉시 터치를 받지 않는다(`.screen`은 `pointer-events: none`, `.screen.active`만 `auto`). 페이드아웃되는 0.45초 동안 새 화면의 터치를 가로채지 않게 하기 위해서다.
- 축하 효과: 화면 일부(축하 친구 주변)에만, 2~3초 이내. 화면 전체를 덮는 폭죽·색종이 금지.
- 이모지는 원색이 강하므로 배경 위 연한 원형 받침(--surface) 위에 올려 대비를 누그러뜨린다. 일러스트 교체 시 위 팔레트 톤으로 제작.
- 부모 설정에 "화면 밝기 낮춤" 옵션 제공(전체에 반투명 웜톤 레이어 적용, 기본 꺼짐).

## 2. 축하 친구들
- 임무(한 판 또는 한 문제) 성공 시 귀여운 캐릭터 친구가 화면 가장자리에서 등장해 축하한다.
- 기본 친구 (모두 오리지널 디자인, 둥글고 귀여운 형태, 위 파스텔 팔레트 톤):
  - 콩콩이: 메인 안내 캐릭터 (동그란 콩 모양)
  - 티노: 아기 티라노사우루스 (세이지 그린, 짧은 팔로 박수)
  - 부릉이: 꼬마 버스 (버터 옐로, 바퀴로 통통 뛰며 "빵빵!")
  - 이후 친구 추가 가능하도록 js/assets.js에 배열로 관리.
- 등장 방식:
  - 문제 하나 정답: 친구 1명이 옆에서 고개를 내밀고 반응(약 2.5초, 통통 3번) + "잘했어!" 등 음성. (처음 1~1.5초 → 실제로 보니 너무 짧다는 사용자 의견으로 2.5초. 축하 효과 2~3초 규칙 안)
  - 한 판 완료: 친구 2~3명이 함께 나와 통통 뛰며 축하(2~3초) + 스티커 지급.
  - 움직임은 위로 통통 튀기·좌우 흔들기·크기 변화만 사용(깜빡임 없음).
  - 축하 대사는 여러 개를 돌려 쓴다: "잘했어!", "최고야!", "우와, 맞았어!", "티노도 신나!", "부릉부릉 출발~!"
- 포도송이 하나를 다 채울 때마다 새 친구(예: 아기 코끼리, 기차 뚜뚜 등 오리지널)가 친구 목록에 합류.
- 초기에는 이모지(🦖, 🚌 등)를 임시로 쓰고, 이후 assets/images/friends/의 SVG로 교체.
- 친구 그림 (SVG, `assets/images/friends/`):
  - 티노 `tino.svg`(세이지), 부릉이 `bureung.svg`(버터), 아기 코끼리 `elephant.svg`(하늘), 기차 뚜뚜 `train.svg`(라벤더). 콩콩이는 CSS 그림(`createKong`) 그대로.
  - 공통 모양: 외곽선 없이 둥근 면, `--ink` 눈(작은 `--surface` 반짝임)과 웃는 입, `--apricot` 볼. 콩콩이와 한 가족처럼 보이게 한다.
  - 버스·기차는 얼굴을 **옆면**에 둔다(앞 유리·앞면 얼굴은 기존 탈것 캐릭터와 닮아 보이므로 피한다, §10).
  - 색은 SVG 안에서도 `style="fill:var(--sage)"`처럼 `:root` 변수로만 쓴다(§1). 그래서 `<img>`가 아니라 `<svg><use href="파일#art">`로 불러온다(변수는 `<use>` 안으로 상속되고, `<img>` 안으로는 전달되지 않는다). 파일을 단독으로 열면 색이 보이지 않는 것이 정상이다.
  - 그림이 있는 친구는 원형 받침 없이 그림만 그린다(받침은 이모지용). `assets.js`의 `image` 값이 있으면 그림, 없으면 이모지로 돌아간다.
  - 부모 설정의 친구 이름 옆 표시는 이모지를 그대로 쓴다(부모 영역은 글자 화면).

### 메인 캐릭터 (한 판마다 바뀜, `js/buddy.js`)
- 메인 화면과 게임 안에서 아이와 함께 있는 캐릭터를 **메인 캐릭터**라 한다. 한 판을 끝까지 마칠 때마다 다른 친구로 바뀐다.
  - 바뀌는 곳: 메인 화면 아래(포도판 버튼 옆), 콕콕 세어 보기 결과 옆, 징검다리를 뛰어 건너는 캐릭터, 한 판 마무리 화면.
  - 콩콩이로 두는 곳: 시작 화면("안녕! 나는 콩콩이야" 인사와 맞춤), 잠금·쉬는 시간 화면, 포도판·보물 상자. 콩콩이는 여전히 앱의 안내 캐릭터다.
- 앱을 켜면 콩콩이로 시작한다. 한 판 마무리 화면(스티커를 받는 화면)까지는 그 판의 캐릭터가 나오고, 그 직후 다음 캐릭터로 바뀌어 메인 화면부터 적용된다. 판을 중간에 그만두면 바뀌지 않는다.
- 후보: 기본 친구 3명 + 합류한 친구(§2). 직전 캐릭터는 고르지 않는다(후보가 1명뿐이면 그대로).
- 고르는 방식(부모 설정 "메인 캐릭터"):
  - **골고루**(기본): 직전 캐릭터를 뺀 후보 중 무작위.
  - **우선순위대로**: 부모가 정한 순서에서 합류한 친구만 남겨, 1순위부터 가중치 2배씩(예: 3명이면 4:2:1). 직전 캐릭터는 뺀다.
- 지금 캐릭터는 저장하지 않는다(§8에 항목을 늘리지 않음). 앱을 다시 켜면 콩콩이부터.
- 그림이 있는 친구는 `.kong.art` 칸 안에 SVG를 그린다. 칸 크기·위치 규칙은 콩콩이와 같고, 정사각 그림을 칸(가로:세로 1:0.82) 안에 맞춰 넣는다(화면 크기 점검 결과를 깨지 않게). 그대로는 콩콩이보다 작아 보여 그림만 아래 가운데 기준으로 1.25배 키운다(배치에는 영향 없음).

### 축하 구현 (`js/celebrate.js`)
- 친구는 `#celebrate-layer` 위에 그린다. 화면 가장자리에만 나오고, 터치는 통과한다.
  - 그림(SVG) 친구는 `createFriendArt()`로, 이모지 친구는 연한 원형 받침 위에, 콩콩이는 `createKong()`으로 그린다.
- 문제 하나 정답(`cheerOne`): 친구 1명이 왼쪽이나 오른쪽 아래에서 옆으로 나와(0.35초) 세 번 통통 뛰고 들어간다(전체 2.5초). 칭찬 음성이 더 길면 음성이 끝날 때까지 기다린다.
- 한 판 완료(`cheerRound`): 친구 2~3명(친구가 3명 이상이면 반반 확률)이 아래 가운데에서 올라와 세 번 통통 뛴다. 0.14초씩 차례로, 2.6초 동안.
- 칭찬 음성 짝: 티노는 `praise_4`, 부릉이는 `praise_5`만 쓴다. 콩콩이와 다른 친구는 `praise_1~3`을 직전과 겹치지 않게 돌려 쓴다.
- 친구 고르기:
  - 직전에 나온 친구는 피한다. 단, 좋아하는 친구는 연속으로 나와도 된다.
  - 좋아하는 친구는 가중치 3이다. 3000번 뽑은 결과 약 65%가 나왔다(다른 친구 각 17%).
- 고를 수 있는 친구 = 기본 친구 3명 + 합류한 친구(`progress.joinedFriends`, 후보는 `assets.js`의 `NEW_FRIENDS`).
- 움직임 줄이기: 옆이나 아래에서 이동하지 않고, 나타났다가 크기 변화(pulse)만 하고 사라진다.
- 진행 중 "처음으로"를 누르면 친구는 즉시 사라진다.

## 3. 스티커와 포도송이 (부모 보상 연계)
- 한 판(3~5문제)을 끝까지 마치면 스티커 1개.
- 스티커 5개가 모이면 포도알 1개로 바뀌어 포도송이에 붙는다(스티커 칸은 다시 0개부터).
- 포도판은 포도송이 총 5개로 구성. 송이당 포도알 수는 부모 설정(기본 10알).
- 포도알이 붙을 때: 빈 알 자리로 포도알이 데굴데굴 굴러가 쓱 들어가는 애니메이션 + "포도알 하나 쓱!" + 현재 개수를 세어 준다("포도알이 일곱 개!") — 숫자 학습과 연결.
- 포도송이 하나를 다 채우면:
  - 축하 친구 전원이 나와 축하(3초, 화면 일부) + 새 친구 합류.
  - 이어서 "보물 상자" 화면: 콩콩이가 "엄마 아빠한테 보여 주자!" 하고 안내.
  - 부모가 미리 등록한 보상이 있으면 그 그림(이모지)을 보여 준다. 보상 글자는 부모용이므로 작게 표시.
  - 부모가 부모 영역에서 "보상 줌" 버튼을 눌러야 해당 송이에 리본(✔ 완료 표시)이 붙는다. 누르기 전까지는 "보상 대기" 상태로 남긴다.
- 5송이를 모두 채우면 "포도판 완성!" 큰 축하 후, 부모가 새 포도판을 시작할 수 있다. 완성한 포도판 수는 기록에 남긴다.
- 메인 화면에 "포도판" 버튼(포도 그림)을 두어 아이가 언제든 볼 수 있게 한다. 포도알 색은 파스텔 라벤더 계열(예: `--grape: #A996C9`), 빈 자리는 연한 점선 원.
- 포도판 로직과 화면은 js/grapes.js에서 관리.
- 포도판 구현 (`js/grapes.js`, 저장 키 `kongkong.grapes`):
  - **데이터:** `board` = { `perBunch`, `startedAt`, `completedAt`, `bunches`[5] }. 각 송이는 `filled`, `completedAt`, `rewardGiven`, `rewardGivenAt`를 가진다. 그 밖에 `boardsCompleted`(완성한 판 수), `history`(지난 판 요약, 최대 50개)를 둔다.
  - **송이당 포도알 수:**
    - 판을 만들 때의 부모 설정 값으로 고정된다.
    - 포도알이 하나도 없는 판은 아직 시작 전으로 보고, 지금 설정을 따른다.
    - 송이 모양은 위가 넓은 줄로 그린다. 5알은 [3,2], 10알은 [4,3,2,1], 15알은 [5,4,3,2,1], 20알은 [6,5,4,3,2]. 알 크기는 50/40/34/28px.
  - **포도알이 들어가는 때:**
    - 메인의 🍇을 열 때와, 한 판을 끝내 스티커 5칸이 찼을 때(이 경우 포도판으로 자동 이동) `pendingGrapes`를 하나씩 꺼내 붙인다.
    - 판이 다 차 있으면 꺼내지 않고 보관한다. 새 포도판을 시작한 뒤 열면 들어간다.
  - **한 알 연출:**
    1. 데이터를 먼저 저장한다(도중에 나가도 포도알은 남는다).
    2. 왼쪽 아래 콩콩이 쪽에서 포도알이 두 바퀴 굴러 빈 자리로 들어간다(1.1초).
    3. `sfx pop`, "포도알 하나 쓱!", 이어서 "포도알이 N 개"(지금 송이 기준)를 말한다.
    4. 움직임 줄이기가 켜져 있으면 굴러가지 않고 자리에서 커졌다 돌아온다.
  - **판 표시:**
    - 지금 채우는 송이는 굵은 포도색 테두리와, 아래에 지금 개수 숫자가 붙는다.
    - 다 채우고 보상 전인 송이는 아래에 🎁(보상 대기)가 붙는다.
    - 보상을 준 송이는 위에 🎀와 ✔가 붙는다.
  - **송이 완성 연출:**
    1. 새 친구 합류를 먼저 저장한다(`NEW_FRIENDS` 순서대로, 모두 합류했으면 없음).
    2. 기존 친구 전원이 3초 축하하며 "포도송이를 다 채웠어!"라고 말한다.
    3. 새 친구가 가운데에 나타나며 "새 친구가 왔어!"라고 말한다.
    4. 보물 상자 화면으로 넘어간다.
  - **보물 상자:**
    - 콩콩이와 🎁가 나오고 "엄마 아빠한테 보여 주자!"라고 말한다. 0.9초 뒤 등록된 보상 그림(크게)과 글(22px, 작게)으로 바뀐다. 보상이 없으면 🎁 그대로 둔다.
    - ▶(160px)를 누르면 닫힌다. ▶는 열린 순간부터 받는다(말하는 도중에 눌러도 바로 닫힘).
  - **포도판 완성:** 모든 송이가 커졌다 돌아오고, 친구 전원이 축하하며 "포도판 완성!"이라고 말한다. `boardsCompleted`가 1 늘어난다. 판은 부모가 새로 시작할 때까지 그대로 둔다.
  - **새 포도판:** 지금 판을 `history`에 요약해 두고, 지금 설정의 송이당 포도알 수로 빈 판을 만든다.
- 스티커 구현:
  - 한 판을 끝내면 마무리 화면에 스티커 칸 5개(⭐)가 보이고, 새 스티커가 쏙(`sfx pop`) 들어간다. 이어서 "한 판 끝! 스티커 받아!"(`line_round_done`)라고 말한다.
  - 5칸이 차면 `progress.js`가 칸을 0으로 비우고 `pendingGrapes`(받을 포도알)를 1 늘린다.
  - grapes.js는 포도판을 열 때 `pendingGrapes`를 꺼내 포도알을 굴려 넣는다(5단계).
  - 한 판 마무리 중 "처음으로"를 눌러도 스티커는 이미 받은 것으로 친다.

## 4. 수 표현
- 부모 설정 "수 읽기 방식"이 우선한다.
  - 고유어(기본값): 1~2단계는 고유어(하나, 둘, 셋…)만 사용. 3단계에서만 한자어를 "3은 '삼'이라고도 해"처럼 소개.
  - 한자어: 단계와 관계없이 한자어(일, 이, 삼…)로 읽는다.
  - 둘 다: 단계와 관계없이 "셋, 삼!"처럼 고유어 다음 한자어를 함께 읽는다.
- 사물 개수 표현("사과가 세 개")은 설정과 관계없이 항상 고유어(우리말 어법상 자연스러운 표현).

## 5. 난이도(적응형)
- 1단계 1~3 / 2단계 1~5 / 3단계 1~10. 처음은 1단계.
- 3연속 정답 → 한 단계 위. 2연속 오답 → 강한 힌트(정답 대상이 커졌다 작아지며 흔들림). 그 후에도 오답 → 한 단계 아래.
- 단계 변화는 아이에게 표시하지 않는다.
- 부모가 단계를 "고정"으로 설정하면 적응형 조정을 끈다.
- 구현(`js/play.js`): 게임마다 단계·연속 정답·연속 오답을 따로 센다. 문제 결과는 `correct`, `hinted`, `wrong` 중 하나다.
  - `correct`: 연속 정답 +1. 3이 되면 한 단계 위로 올리고 0으로 돌린다.
  - `hinted`: 연속 정답만 0으로 돌린다. 단계는 그대로다.
  - `wrong`: 연속 오답 +1. 3번째 오답이면 한 단계 아래로 내린다. 2번째 오답의 강한 힌트는 각 게임이 `missCount()`를 보고 낸다.
- 단계 변화는 콘솔에만 남긴다. 게임별 단계·연속 정답·연속 오답은 `progress.js`에 저장해 앱을 다시 켜도 이어진다.
- 문제 결과는 난이도 설정과 관계없이 항상 정답률 통계로 남긴다. 단계 조정은 "자동"일 때만 한다.

### 게임 진행 공통 (`js/play.js`)
- 한 판의 문제 수는 부모 설정 "한 판 문제 수"를 따른다. 단계와 수 읽기 방식은 문제마다 설정을 다시 읽는다.
- 무응답 힌트는 부모 설정 "힌트 나오는 시점"을 따른다. "바로"를 골라도 최소 1.5초는 기다린다.
- 수 읽기가 "고유어"이고 3단계일 때, 한자어 소개(`n_intro_NN`)는 **한 판에 한 번**(그 판의 첫 문제가 끝난 뒤) 한다.
- 게임 화면 왼쪽 위에 "처음으로"(🏠, 120px) 버튼을 둔다. 누르면 진행 중인 문제·소리·힌트를 모두 멈추고 메인으로 돌아간다.
- 한 판이 끝나면 스티커 1개를 주고(§3), 축하 친구 2~3명이 나온다(§2). 음성은 "한 판 끝! 스티커 받아!"이고, 끝나면 메인으로 돌아간다.
- 게임 모듈 규약: `export default { id, playQuestion(ctx) }`. `ctx`는 `stage`, `level`, `range`, `numberStyle`, `hintDelayMs`, `first`, `introNeeded`, `misses`(직전까지 연속 오답 문제 수), `signal`을 담는다.
- 게임끼리 겹치는 도우미(`randInt`, `shuffle`, `el`, `wait`, `makePicker`, `pickChoices`, `pickComparePair`, `makeSidePicker`, `pickStoneRun`, `shuffleStoneSlots`, `MAX_IDLE_HINTS`)는 `js/games/common.js`에 둔다. DOM이 필요 없는 함수는 Node에서 바로 검사할 수 있다. `signal`이 중단되면 게임은 즉시 정리하고 `{ aborted: true }`를 돌려준다.

## 6. 미니게임
1. count — 콕콕 세어 보기: 물체를 탭할 때마다 살짝 커지며 테두리가 생기고 "하나, 둘…", 끝나면 "사과가 세 개!"
2. choose — 몇 개일까?: 물체 묶음 + 숫자 카드 2~3장 중 선택
3. basket — 바구니 채우기: "딸기 네 개 담아 줘" → 탭해서 담기, 담을 때마다 세기
4. compare — 어느 쪽이 많아?: 두 접시 중 많은 쪽 탭
5. stones — 징검다리: 1→2→3 순서대로 돌을 밟아 건너기

### count 상세 (`js/games/count.js`)
- **문제:** 물체 n개를 한 종류로 보여 준다. 한 줄에 최대 5개, 크기는 120~170px, 간격은 24px 이상이다.
  - n은 단계 범위에서 고른다. 단, 2·3단계는 2부터 낸다(1개 세기는 너무 쉬움).
  - 직전 문제와 같은 수, 같은 물체는 피한다.
- **탭할 때:**
  - 물체가 `mark`(1.1배, 굵은 테두리)되고 `pulse`한다. 오른쪽 위에 센 순서 숫자 배지가 붙는다(화면 글자는 숫자만).
  - `sfx tap`과 함께 수를 읽는다(부모 설정의 수 읽기 방식). 빨리 탭하면 앞의 수를 끊고 새 수를 읽는다.
  - 이미 센 물체를 다시 누르면 부정 반응 없이, 다음에 셀 물체만 살짝 커졌다 돌아온다.
- **다 세면:** 마지막 수를 끝까지 읽고 `sfx correct`, 큰 숫자 카드 등장, "사과가 세 개"(항상 고유어)를 말한다. 필요하면 한자어 소개를 하고, 축하 친구 1명이 나와 칭찬한다(`cheerOne`).
- **힌트:** 가만히 있으면 다음에 셀 물체를 알려 준다.
  - 1차: 2번 커졌다 돌아오며 "이건 어때?"
  - 2·3차: 3번 커졌다 돌아온 뒤 2번 흔들며 "콕콕 눌러서 세어 보자!"
  - 3번 알려 준 뒤에는 멈추고, 아이가 물체를 누르면 다시 셀 수 있다(§1 힌트 상한).
- **결과:** 틀리는 경우가 없다. 힌트 없이 끝내면 `correct`, 힌트가 나왔으면 `hinted`다. 그래서 count에서는 단계가 내려가지 않는다.
- 시작 안내("콕콕 눌러서 세어 보자!")는 한 판의 첫 문제에서만 말한다.

### choose 상세 (`js/games/choose.js`)
- **문제:**
  - 물체 n개 묶음을 위에 보여 준다. 누르는 대상이 아니라서 90~120px로 count보다 작다(120px 최소 규칙에서 제외). 한 줄에 5개씩(5개 단위 묶음) 놓는다: 7개는 5+2, 10개는 5+5.
  - 아래에는 숫자 카드(150×180px, 간격 32px 이상)를 둔다. 1단계는 2장, 2·3단계는 3장이다.
  - n과 물체는 count와 같은 규칙으로 고른다(2단계 이상 2부터, 직전과 다른 수·물체).
  - 오답 카드는 정답과 가까운 수(±2)를 먼저 쓰고, 모자라면 먼 수로 채운다. 카드 순서는 섞는다(`common.js`의 `pickChoices`).
  - **정답이 "제일 큰 수"로 굳지 않게:**
    - 오답 카드에는 범위보다 **하나 큰 수**까지 쓸 수 있다(최대 10). 예: 2단계(1~5)에서 정답이 5면 6도 오답 후보. 정답은 늘 범위 안의 수다.
    - 정답 카드가 몇 번째 크기(가장 작음·가운데·가장 큼)일지를 **가능한 자리 중에서 고르게** 먼저 정하고, 그에 맞춰 아래·위 오답을 고른다.
    - 정답이 1이면 늘 가장 작은 수, 3단계에서 10이면 늘 가장 큰 수인 것은 피할 수 없다(0·11은 쓰지 않음).
- **음성:** 매 문제 "몇 개일까?"를 말한다. 한 판의 첫 문제에는 "맞는 숫자를 콕 눌러 줘!"를 이어서 말한다.
- **정답:**
  - 나머지 카드가 사라지고, 정답 카드가 mark·pulse된다. `sfx correct`와 함께 수를 읽는다.
  - 물체에 1, 2, 3… 배지가 차례로 붙는다(소리 없이, 이미 세어 줬으면 생략).
  - "사과가 세 개"(항상 고유어), 필요하면 한자어 소개, 이어서 축하 친구(`cheerOne`)가 나온다.
- **오답:** 부정 효과음은 없다.
  - 누른 카드의 수를 읽어 주고, 그 카드는 흐려지고 작아져 다시 누를 수 없다.
  - "다시 한번 해 볼까?"와 함께 정답 카드가 살짝 흔들린다.
- **강한 힌트:** 한 문제에서 두 번째로 틀렸을 때 나온다. 직전까지 두 문제를 연속으로 틀렸으면(`ctx.misses ≥ 2`) 첫 오답부터 나온다.
  - 물체를 하나씩 소리 내어 센다(배지 + mark). 그다음 정답 카드가 3번 커졌다 돌아오고 2번 흔들린다.
  - 세는 동안에는 탭을 받지 않는다.
- **무응답 힌트:** 1차는 물체가 커졌다 돌아오며 "몇 개일까?"를 다시 묻는다. 2·3차는 강한 힌트와 같다. 3번 뒤에는 멈추고, 카드를 누르면 다시 셀 수 있다(§1 힌트 상한).
- **결과:** 한 번에 맞히면 `correct`, 무응답 힌트 뒤 맞히면 `hinted`, 한 번이라도 틀리면 `wrong`(number = 정답 n, 자주 틀리는 숫자 통계용). 오답인 문제가 연속 3번이면 단계가 내려간다(§5).

### basket 상세 (`js/games/basket.js`)
- **문제:**
  - 목표 n은 count와 같은 규칙으로 고른다(2단계 이상 2부터, 직전과 다른 수).
  - 물체는 바구니에 어울리는 사과·딸기·꽃·물고기만 쓴다(병아리·풍선 제외).
  - 화면 왼쪽에 **목표보다 더 많은** 물체를 놓는다. 1단계는 +2, 2·3단계는 +3, 최대 13개. 목표 개수에서 멈추기를 배우게 하려는 것이다.
  - 물체는 120~140px, 한 줄 5개, 간격 24px 이상이다. 오른쪽에는 바구니(200~240px 원, 🧺 + 담긴 개수 숫자 배지)와 그 위에 담긴 물체를 작게(44px, 한 줄 5개) 모아 둔다.
- **음성:** 매 문제 "딸기 네 개 담아 줘!"(`sayBasketAsk`, 개수는 항상 고유어)를 말한다. 목표 수를 듣는 것이 이 게임의 핵심이다.
- **담기:**
  - 누르면 `sfx pop`과 함께 물체가 바구니로 포물선을 그리며 날아간다(0.5초). 자리는 투명하게 남겨 배치가 흔들리지 않게 한다.
  - 바구니 숫자가 늘고 위에 작은 물체가 쌓이며, 수를 읽는다(부모 설정 수 읽기 방식).
  - 움직임 줄이기가 켜져 있으면 날아가지 않고 바로 담긴다.
- **끝:**
  - 목표 개수에 닿으면 **자동으로 끝난다.** 그 순간부터 더 담을 수 없어 넘치게 담는 오답이 없다(연타해도 정확히 n에서 멈춤).
  - 남은 물체가 사라지고 바구니 테두리가 금빛으로 바뀐다. 이어서 "딸기가 네 개" → (3단계·고유어면 한자어 소개) → "바구니 가득! 고마워!" → 축하 친구 순서로 나온다.
- **무응답 힌트(연달아 최대 3번):**
  - 1차: 담을 물체와 바구니가 커졌다 돌아온다(소리 없음).
  - 2·3차: 요청을 다시 들려주고, 담을 물체가 3번 커졌다가 2번 흔들린다.
  - 하나라도 담으면 다시 0부터 센다.
- **결과:** 힌트 없이 끝내면 `correct`, 무응답 힌트가 나왔으면 `hinted`. 틀리는 경우가 없어 basket에서는 단계가 내려가지 않는다.

### compare 상세 (`js/games/compare.js`)
- **문제:** 같은 물체를 담은 접시 두 개를 좌우에 놓는다.
  - 접시 전체가 누르는 대상이다(약 460×370px, 두 접시 크기 같음, 간격 48px 이상).
  - 물체는 누르는 대상이 아니라서 56~72px로 작게, 접시 안에 한 줄 5개씩 놓는다(5개 묶음).
  - 물체 종류는 6종 중 직전과 다른 것.
- **수 조합**(`common.js`의 `pickComparePair`, 직전과 같은 조합은 피함):
  - 1단계: 1~3 중 서로 다른 두 수(3가지)
  - 2단계: 1~5 중 차이 2 이상(6가지, 눈으로 비교하기 쉬움)
  - 3단계: 2~10 중 차이 1~3(21가지, 가까운 수 비교)
- **많은 쪽 위치:** 왼쪽·오른쪽 무작위, 같은 쪽이 3번 연속 나오지 않게 한다(`makeSidePicker`).
- **음성:** 매 문제 "어느 쪽이 더 많아?"를 말한다.
- **정답:** 많은 쪽 접시가 mark·pulse되고 `sfx correct`가 난다. 두 접시 위에 개수 숫자가 나타난다(많은 쪽은 금빛·굵은 테두리). 이어서 "사과가 다섯 개"(많은 쪽, 항상 고유어) → (3단계·고유어면 한자어 소개) → "이쪽이 더 많아!" → 축하 친구.
- **오답:** 부정 효과음은 없다. 누른 접시가 살짝 커졌다 돌아오고, "다시 한번 해 볼까?"와 함께 많은 쪽 접시가 흔들린다. 보기가 둘뿐이라 틀린 접시를 막지는 않는다.
- **강한 힌트:** 한 문제에서 두 번째로 틀렸을 때 나온다. 직전까지 두 문제를 연속으로 틀렸으면 첫 오답부터 나온다.
  - "다시 한번 해 볼까?"를 끝까지 말한 뒤, 왼쪽·오른쪽 접시 물체를 차례로 하나씩 소리 내어 센다(배지 + mark).
  - 그다음 많은 쪽 접시가 3번 커졌다 돌아오고 2번 흔들린다. 세는 동안은 탭을 받지 않는다.
- **무응답 힌트(연달아 최대 3번):** 1차는 두 접시가 커졌다 돌아오며 다시 묻는다. 2·3차는 강한 힌트와 같다.
- **결과:** 한 번에 맞히면 `correct`, 무응답 힌트 뒤면 `hinted`, 한 번이라도 틀리면 `wrong`(number = 많은 쪽 수).

### stones 상세 (`js/games/stones.js`)
- **화면:** 왼쪽 강둑(콩콩이 시작) · 가운데 강(`--sky` 띠) · 오른쪽 강둑(🌳 목표).
  - 돌은 120~136px이고 숫자만 쓴다. 강 안에서 왼쪽부터 위·아래를 번갈아(지그재그) 놓는다.
- **돌 숫자**(`common.js`의 `pickStoneRun`, 직전과 같은 구간은 피함):
  - 1단계: 1·2·3
  - 2단계: 4개(1~4 또는 2~5)
  - 3단계: 1~10 안에서 이어지는 5개(시작 1~6)
  - 1280px 화면에 120px 돌을 간격을 지켜 놓으려면 한 화면에 5개가 한계다. 그래서 3단계는 1~10 전체 대신 이어지는 5개로 하고, 중간에서 시작하는 수 순서를 연습하게 했다.
- **돌 자리**(`shuffleStoneSlots`): 숫자 순서와 다르게 섞는다. 왼쪽부터 누르기만 하면 숫자를 몰라도 건너게 되므로, 2단계 이상은 우연히 순서대로 놓인 배치도 피한다. 1단계(3개)는 섞지 않은 배치도 허용한다.
- **음성:** 매 문제 "처음부터 차례대로 건너 보자!"를 말한다.
- **맞는 돌:** 돌이 mark(1.1배 + 진한 테두리)되고, 콩콩이가 그 돌 위로 포물선을 그리며 뛰어오른다(0.45초). 그 수를 읽는다(부모 설정 수 읽기 방식). 뛰는 동안은 탭을 받지 않는다. 이미 밟은 돌은 다시 눌러도 반응하지 않는다.
- **틀린 돌:** 부정 효과음은 없다. 누른 돌이 살짝 커졌다 돌아오고, 다음에 밟을 돌이 흔들리며 그 수를 들려준다("셋!").
  - 이 문제에서 두 번째 오답부터(직전 두 문제 연속 오답이면 첫 오답부터)는 강한 힌트다: 다음 돌이 3번 커졌다 돌아오고 2번 흔들리며 수를 들려준다.
- **다 건너면:** 콩콩이가 건너편 나무로 뛰고 `sfx correct`가 난다. 이어서 "와, 다 건넜다!" → (3단계·고유어면 마지막 돌 수의 한자어 소개) → 축하 친구.
- **무응답 힌트(연달아 최대 3번):** 1차는 다음 돌만 소리 없이 커졌다 돌아온다. 2·3차는 강한 힌트와 같다.
- **움직임 줄이기:** 콩콩이가 뛰지 않고 바로 다음 자리로 옮겨진다.
- **결과:** 한 번에 `correct`, 무응답 힌트 뒤 `hinted`, 한 번이라도 틀리면 `wrong`(number = 처음 못 찾은 수).

## 7. 음성
- assets/audio/*.mp3를 우선 재생. 파일이 없으면 Web Speech API(ko-KR, rate 0.85)로 대체.
- 필요한 음성 문장 목록은 assets/audio/LIST.md에 파일명과 함께 관리한다.
- 첫 터치 전에는 소리가 막히므로, 시작 화면에서 큰 "시작" 버튼 탭으로 오디오를 활성화한다.
  - 활성화(`AudioContext.resume()`)는 기기에 따라 끝나지 않을 수 있으므로 **최대 0.8초만 기다리고** 메인으로 넘어간다(시작 화면 멈춤 방지). 음성 재생 직전의 `resume()`도 같은 시간 제한을 둔다. 활성화는 뒤에서 계속되고, 실패하면 TTS로 읽는다.
- 문장 데이터의 정본은 `js/lines.js`다(키 = mp3 파일명). `assets/audio/LIST.md`는 이 데이터로 만든 녹음용 목록이며, 개발 테스트 화면의 "LIST.md 대조"로 두 목록이 일치하는지 확인한다.
- 조각 문장("사과가" + "세 개", "딸기" + "네 개" + "담아 줘!", "포도알이" + "일곱 개")은 조각 mp3가 **모두 있을 때만** 이어 재생하고, 하나라도 없으면 문장 전체를 TTS로 읽는다(목소리가 섞이지 않게).
- 새 음성을 시작하면 말하던 음성은 끊는다(기본). 아이가 연달아 탭해도 소리가 겹치지 않게 하기 위해서다.
- 음성 속도 설정(느리게 0.85 / 보통 1.0)은 TTS에만 적용한다. mp3는 천천히 녹음한다.
- **효과음 소리: 글로켄(벨)** — 사용자가 비교 화면(`dev/sfx.html`)에서 피아노·부드러운 피아노·벨·오르골 중 골랐다.
  - 음 하나 = 사인파 부분음 4개(주파수 비 1 : 2.76 : 5.4 : 8.93, 세기 1 : 0.35 : 0.12 : 0.05)의 합. 정수배가 아니어서 종소리가 난다.
  - 2ms 만에 올라간 뒤 지수로 줄어든다. 줄어드는 시간은 (0.6 × 음 길이) ÷ (1 + 0.9 × 부분음 순서)로, 높은 부분음이 먼저 사라진다.
  - 효과음 4종: 톡 660Hz(0.35초, 세기 0.55) / 띵동 784→1047Hz(0.16초 뒤) / 쏙 440→880Hz로 올라감 / 짜잔 523·659·784Hz 0.15초 간격.
  - **크기:** 태블릿에서 잘 들리게(실기기에서 두 번 "작다") 효과음 음량 × 2.4배로 보낸 뒤 리미터(threshold −3dB, ratio 20)를 거쳐 × 0.8로 낸다. 벨은 시작이 빨라 리미터만으로는 최대 1.20까지 튀어서 마지막에 줄였다. 측정 최대 0.96(음량 100% 짜잔), 음량 60% 띵동 소리 에너지 −10dB(처음 −36dB).
- **기기에 한국어 TTS 음성이 없으면 음성이 전혀 나오지 않는다**(말하기 요청에 시작·오류 신호가 모두 없음). 갤럭시탭에서는 Galaxy Store에서 삼성 TTS 한국어 음성을 받아 해결했다. 부모 화면 "목소리"에 한국어 목소리가 없을 때 이 안내를 보여 준다.
- **음성 진단(부모 설정 → 소리):** TTS가 안 들리는 기기에서 원인을 찾기 위한 화면. 브라우저·목소리 목록(한국어, 기기/인터넷)·오디오 상태와, 시험 말하기 3가지(앱 방식 / 목소리 지정 없이 / 멈춤(cancel) 없이 바로)의 결과(시작됨·끝까지 말함·오류 코드·응답 없음), 최근 말하기 8건을 글자로 보여 준다. 저장하지 않는다.
- **TTS에 넘기기 전 기호 지우기(`cleanForSpeech`):** 글자·숫자·띄어쓰기와 문장부호 `. , ! ?`만 남긴다. `~`는 그냥 지우고, 나머지 기호(따옴표, 괄호, `·`, `…`, 이모지 등)는 띄어쓰기로 바꾼다(따옴표를 붙여 지우면 "둘은 이라고도"처럼 숫자가 조사에 묻힌다). TTS가 "물결표"처럼 기호 이름을 읽기 때문이다. `lines.js`의 문장은 녹음 대본(LIST.md)이기도 하므로 `~` 같은 억양 표시는 그대로 둔다.
- **TTS 목소리 고르기:**
  - 기기의 한국어 음성 중 가장 자연스러운 것을 자동으로 고른다. 점수: 이름에 Natural·Neural +10, Google·Samsung +6, 선히(SunHi) +3, Online +2, Multilingual −1, 오래된 기계 음성(Heami) −5.
  - 인터넷이 끊겨 있으면(`navigator.onLine === false`) 기기에 저장된 음성(`localService`)만 쓴다.
  - 온라인 음성이 오류를 내면 그 문장을 기기 음성으로 한 번 다시 읽는다(소리가 아예 안 나는 일이 없게).
  - 부모 설정 "목소리"에서 직접 고를 수 있다(`voiceName`, 빈 값 = 자동). 고른 음성이 없거나 오프라인이라 쓸 수 없으면 자동 선택으로 돌아간다.
  - 참고(2026-11 기준): Windows Edge에는 Heami(기기, 기계음)와 선히·인준·현수(온라인, Natural)가 있다. 갤럭시탭 Chrome에서는 그 기기의 Google·삼성 음성이 나온다.
- 숫자 음성: 세기(고유어)·개수는 1~20(포도알 최대 20), 한자어·한자어 소개는 1~10. 수 읽기가 "한자어"·"둘 다"여도 10을 넘는 수는 고유어로 읽는다.
- 효과음 4종(tap·correct·pop·cheer): `sfx_*.mp3`가 없으면 부드러운 사인파 합성음으로 대신한다. 부정 효과음은 없다.
- 공개 함수(`js/audio.js`): `unlockAudio`, `configure`, `say`, `stop`, `sayNumber`, `sayAmount`, `sayBasketAsk`, `sayGrapeCount`, `sayIntro`, `sayPraise`, `sfx`, `preload`, `hasFile`.

## 8. 저장
- localStorage에 게임별 단계, 스티커, 포도판(송이별 포도알 수·보상 내용·보상 줌 여부·완성 판 수), 합류한 친구, 오늘 이용 시간, 정답률, 부모 설정만 저장.
- 브라우저 데이터 삭제 시 기록이 사라지므로, `navigator.storage.persist()`를 요청해 자동 삭제를 막는다.
- 저장 키는 모두 `kongkong.`으로 시작한다(백업·복원 대상 판별에 사용). 부모 설정은 `kongkong.settings` 하나에 JSON으로 저장한다.
- 진행 기록은 `kongkong.progress`(`js/progress.js`)에 저장한다. 담는 것:
  - 게임별 `level`, `streak`, `misses`
  - 게임별 `stats`(questions, correct, hinted, wrong), `wrongNumbers`(틀린 정답 수 → 횟수)
  - `stickers`(0~4), `stickersTotal`, `roundsCompleted`, `pendingGrapes`, `joinedFriends`
- 진행 기록 저장 방식:
  - 읽을 때마다 `sanitize()`로 검증하고, 캐시 없이 매번 저장소에서 읽는다(백업 복원 직후에도 최신).
  - 저장소를 쓸 수 없으면 이번 실행 동안만 메모리에 기억한다.
- 포도판은 별도 키(`kongkong.grapes`, §3)에 둔다. "진행 초기화"(`resetProgress`)는 단계, 스티커, 합류한 친구만 지운다. 포도판, 받을 포도알, 학습 통계는 남긴다.
- 이용 시간은 `progress.usage`에 날짜(로컬 `YYYY-MM-DD`)별 초로 저장한다. 하루 최대 86400초이고 최근 30일만 보관한다. 진행 초기화로는 지워지지 않는다.
- 진행 기록·포도판의 메모리 기록은 저장소 자체를 쓸 수 없을 때(예외)만 쓴다. 저장소에 값이 없으면(복원·삭제 직후) 기본값으로 시작하고 옛 메모리를 되살리지 않는다.
- `navigator.storage.persist()`는 시작 버튼을 탭할 때 요청한다. 허용 여부는 브라우저가 정한다(설치된 PWA는 대개 허용).

## 9. 부모 영역
- 화면 모서리 아이콘을 3초 길게 눌러야 진입. 진입 후 간단한 덧셈 문제(예: 7+5) 정답 입력으로 한 번 더 확인.
- 부모 영역 화면의 글자 사용은 CLAUDE.md 유아 UX 원칙 1의 예외 조항을 따른다.
- 진입 아이콘: 메인 화면 오른쪽 위, 84px, 반투명(⚙️ 회색). 아이용 터치 대상이 아니므로 120px 규칙에서 제외하고 눈에 덜 띄게 둔다. 누르는 동안 테두리 링이 3초에 걸쳐 차오르고(크기 1.12배), 손을 떼거나 버튼 밖으로 벗어나면 취소된다. 짧게 누르면 아무 반응이 없다.
- 덧셈 확인: 3~9 사이 두 수의 받아올림 덧셈(합 10 이상)을 무작위로 낸다. 숫자 키패드로 최대 두 자리까지 입력한다. 오답이면 입력칸을 흔든 뒤 새 문제를 낸다. 30초 동안 입력이 없거나 "취소"를 누르면 아이 화면으로 돌아간다.

### 이용 시간 구현 (`js/usage.js`)
- **세는 시간:** 아이 화면(메인·게임·포도판)이 보이는 동안만 1초씩 센다. 시작·부모 영역·잠금·쉬는 시간 화면, 앱이 백그라운드일 때는 세지 않는다. 10초마다, 앱이 숨겨질 때, 자정이 지날 때 저장한다.
- **잠금 이유:** `hours`(이용 가능 시간대 밖)를 `daily`(오늘 사용 ≥ 하루 이용 시간)보다 먼저 본다.
- **이용 가능 시간대 판정:**
  - 시작 < 끝이면 [시작, 끝) 안일 때 허용한다.
  - 시작 > 끝이면 밤을 넘기는 구간으로 보아, 지금 ≥ 시작 또는 지금 < 끝일 때 허용한다.
  - 시작 = 끝이면 하루 종일 잠긴다. 부모 화면에서 저장할 때 경고한다.
- **잠그는 시점:**
  - 메인·포도판에서는 바로 잠근다(포도판 연출을 멈춘다. 포도알은 이미 저장되어 있다).
  - 게임 중에는 문제와 문제 사이(`checkpoint`)에서 잠근다. 단, 잠금 사유가 생긴 뒤 120초가 지나면 문제 도중이라도 잠근다.
  - 마지막 문제까지 마친 판은 스티커를 준 뒤에 잠근다(받을 포도알은 다음에 포도판을 열 때 붙는다).
- **잠금 화면:** 콩콩이와 🌙만 있고 글자는 없다. 들어갈 때 "오늘은 여기까지! 내일 또 만나~"라고 말한다.
  - 오른쪽 위에 부모 진입 버튼(3초 길게 누르기)이 있다.
  - 1초마다 다시 확인해, 자정·시간대 시작·부모가 제한을 늘린 경우 저절로 메인으로 돌아간다.
  - 메인으로 가는 모든 전환(시작, 부모 나가기, 처음으로)은 `showScreen`에서 잠금 여부를 확인해 잠금 화면으로 보낸다. 게임·포도판 버튼도 누를 때 확인한다.
- **쉬는 시간 알림:**
  - 연속 이용이 설정 분에 이르면 띄운다. 메인에서는 바로, 게임 중에는 문제 사이에서, 포도판에서는 메인으로 돌아온 뒤에 띄운다.
  - 화면에는 콩콩이와 🌳가 나오고 "눈도 쉬어야 해. 저 멀리 한번 볼까?"라고 말한다.
  - 20초 뒤 ▶가 천천히 나타나고, 그 전에는 눌러도 반응하지 않는다. ▶를 누르면 "눈이 쉬었어! 다시 놀자!"라고 말하고 연속 이용을 0으로 돌린다.
  - 쉬는 동안은 이용 시간을 세지 않는다. 앱을 60초 이상 떠나 있었으면 연속 이용을 0으로 본다.

### 학습 기록 (부모 설정 "기록 > 학습 기록")
- **게임별 정답률 표:** 게임, 푼 문제 수, 한 번에 맞힘(막대 + %), 힌트 후 맞힘 %, 틀린 적 있음 %, 지금 단계(자동이면 게임별 단계, 고정이면 고정 단계)를 보여 준다. 막대를 누르면 자세한 수가 알림으로 나온다.
- **최근 7일 이용 시간:**
  - 막대 7개(색 하나 `--grape`). 막대마다 분 값을 글자로 붙인다(1분 미만은 "1분 미만").
  - 오늘은 막대 테두리와 "오늘" 글자로 구분한다. 점선은 하루 이용 시간 제한이다.
  - 막대를 누르면 날짜와 정확한 시간이 알림으로 나온다.
  - 파스텔이라 막대 대비가 3:1 미만이므로 값 글자를 반드시 함께 둔다(dataviz 검증 결과).
- **자주 틀리는 숫자:** 모든 게임의 `wrongNumbers`를 합쳐 많이 틀린 순으로 상위 5개(숫자 · N번)를 보여 준다. 없으면 안내문을 보여 준다.
- **모은 것:** 끝까지 마친 판 수, 받은 스티커 수, 완성한 포도판 수.
- 시간 탭 맨 위 "오늘 이용 현황": 오늘 사용 시간 / 하루 제한 · 남은 시간, 잠금 상태와 이유.

### 부모 설정 구현 규칙
- 데이터는 `js/settings.js`, 화면은 `js/parent.js`가 맡는다. 다른 모듈은 `getSettings()`/`getSetting(path)`로 읽고, `onSettingsChange(cb)`로 변경을 받는다.
- 저장된 값은 읽을 때마다 `sanitize()`를 거친다. 선택지 밖의 값이나 잘못된 값은 기본값으로 돌아간다. `setSetting()`은 허용되지 않는 값을 저장하지 않고 `false`를 돌려준다.
- 게임은 최소 1개 켜져 있어야 한다. 마지막 게임을 끄려 하면 막고 안내한다.
- 이용 가능 시간대: 끝 시각이 시작보다 이르면 다음 날 그 시각까지로 본다. 시작과 끝이 같으면 하루 종일 잠기며, 저장할 때 경고한다(아래 "이용 시간 구현").
- 보상 글은 최대 30자. 보상 그림은 정해진 이모지 12개(🍦🧸🏞️📚🎈🎁🍰🎨🧩🚲🎡🍕) 중에서 고르거나 없음.
- 화면 밝기 낮춤: `html[data-dim="on"]`일 때 `#dim-layer`(`--dim-layer` 반투명 웜톤)를 화면 전체에 덮는다. 터치는 통과한다.
- 각 항목에 상태 배지를 단다: "바로 적용"(지금 동작에 반영됨), "값만 저장 · N단계에서 연결", "준비 중 · N단계"(버튼 비활성). 기능을 연결하면 해당 항목의 배지를 "바로 적용"으로 바꾼다.
- 부모 설정 화면에서 3분 동안 조작이 없으면 아이 화면으로 돌아간다.
- 백업 파일 형식: `{ app: "kongkong", format: 1, exportedAt, data: { "kongkong.*": "<저장 문자열>" } }`, 파일명은 `kongkong-backup-YYYYMMDD.json`. 불러올 때 형식을 검사하고 확인 창을 1번 띄운 뒤, 기존 `kongkong.*` 항목을 모두 바꾼다.
- 되돌리기 어려운 작업(포도판 새로 시작, 진행 초기화)은 `confirmTwice()`로 두 번 확인한다.
- 진행 초기화: 지금 상태(게임별 단계, 스티커 칸, 합류한 친구 수)를 보여 준다. 두 번 확인한 뒤 `resetProgress()`로 단계·연속 기록·스티커 칸·합류한 친구만 되돌린다. 포도판, 받을 포도알, 정답률·틀린 숫자, 이용 시간, 누적 스티커·판 수는 남긴다. 2차 확인 문구에서 백업을 권한다.
- 보상 줌 처리: 송이 5개의 상태를 한 줄씩 보여 준다(진행 중 N/M알, 🎁 보상 대기, 🎀 ✔ 보상 줌 날짜)와 등록된 보상. "보상 대기" 송이에만 [🎀 보상 줌] 버튼이 있고, 확인 1회를 거친다. 되돌리기는 없다.
- 포도판 새로 시작: 지금 판 요약(완성 송이 수, 포도알 수, 송이당 알 수), 완성한 판 수, 아직 넣지 않은 포도알 수를 보여 준다. 설정이 다르면 "새 포도판은 송이당 N알로 시작합니다"라고 안내한다.
- 부모 영역의 누르는 대상은 어른용이므로 아이 화면의 120px 규칙 대신 **최소 40px**로 한다(칩 48~56px, 키패드 76px, 정답률 막대 버튼 40px). 부모 진입 아이콘(84px)은 위 예외를 따른다.

## 11-1. 배포 (GitHub Pages)
- 저장소 루트를 그대로 Pages로 내보낸다(Branch `main`, 폴더 `/ (root)`). 빌드 단계는 없다.
- `.nojekyll`로 Jekyll 변환을 끈다. `.gitignore`로 `_bak/`은 올리지 않는다.
- 무료 계정의 Pages는 **공개 저장소**여야 하므로 `CLAUDE.md`·`docs/`도 공개된다(`dev/`·`_bak/`은 `.gitignore`로 올리지 않는다). 이 파일들에 아이 이름·연락처 등 개인정보를 쓰지 않는다.
- 저장소 이름은 영문으로 하고 아이 이름을 넣지 않는다. 주소는 `https://<아이디>.github.io/<저장소>/`이며, 모든 경로가 상대경로라 하위 경로에서도 동작한다.
- 업데이트: 파일 수정 → `sw.js`의 `CACHE_VERSION` 올림 → 커밋·푸시 → 1~2분 뒤 반영. 태블릿에서는 앱을 한 번 열면 새 버전을 받고, 다음에 열 때부터 적용된다(캐시 우선).
  - 자동 적용(`main.js` `registerServiceWorker`): 새 service worker가 화면을 넘겨받으면 시작 화면에서는 바로 새로고침하고, 다른 화면이면 놀이를 끊지 않고 앱을 떠났다 돌아올 때 새로고침한다. 앱으로 돌아올 때마다 새 버전을 확인한다. 첫 설치 때는 새로고침하지 않는다.
- mp3를 추가하면 `sw.js`의 `ASSETS`에도 넣는다. 넣지 않으면 온라인에서 한 번 재생된 파일만 오프라인에서 나온다.
- 저장된 기록(localStorage)은 기기·브라우저·주소(origin)별이다. GitHub 아이디를 바꾸면 주소가 바뀌어 기록이 보이지 않으므로, 그 전에 부모 메뉴에서 백업한다.
